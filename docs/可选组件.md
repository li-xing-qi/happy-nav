# 可选组件：dsh 与 EasyTier

> 本文回答一个常见问题：**想复刻完整效果，要不要把 dsh 和 EasyTier 一起打包分发？**
>
> 简短答案：**不要打包。** 它们是独立的第三方软件，属于「运行环境」而不是「本项目的代码」。
> 本文给出许可证事实、正确的接入方式，以及不分发时怎么让使用者快速上手。

---

## 一、先分清三件事

很多人把这三样混在一起，导致既担心侵权、又做不好体验：

| 类别 | 是什么 | 是否属于本项目 |
|---|---|---|
| **本项目代码** | 站点、四个玩法、四层记忆模块 | ✅ 是，MIT/非商业许可，随仓库分发 |
| **模型服务** | 任何 OpenAI 兼容接口（本地 Ollama、云 API 都行） | ❌ 不是，由使用者自己选、自己填 |
| **运行环境组件** | dsh（AI 能动手干活）、EasyTier（异地组网） | ❌ 不是，独立软件，独立许可证 |

**只有第一类是你的东西。** 后两类打包进去，法律上是「你在再分发别人的软件」，要承担相应义务；工程上还会把配置和密钥一起带出去。

## 二、两个组件的许可证事实

核实时间：2026-11，以官方仓库为准，**升级前请自行复核**。

### dsh

| 项 | 内容 |
|---|---|
| 包名 | `@deepseek-ai/dsh` |
| 许可证 | **MIT** |
| 来源 | npm 官方源（DeepSeek 发布） |
| 它能带来 | 让 AI 真的能跑命令、读文件、画图；本项目的「与鱼」通道若接上它，才有"干活"能力 |
| 不装会怎样 | 只是聊天与棋牌，AI 不能操作任何东西 |

**MIT 的含义**：可以自由使用、修改、再分发，只需保留版权声明与许可证文本。所以**法律上允许打包**。

**但技术上没必要**：一条命令就能装，打包反而是替用户锁死版本。

```bash
npm install -g @deepseek-ai/dsh
```

**完整接入步骤**（登录授权、OneBot 配置、桥接部署、验证、排错）见
**[接入dsh.md](接入dsh.md)**，本仓库还附带了可直接运行的桥接脚本 `bridge/yufish-bridge.js`。

### EasyTier

| 项 | 内容 |
|---|---|
| 项目 | EasyTier（去中心化 mesh VPN，支持 WireGuard） |
| 许可证 | **LGPL-3.0** |
| 来源 | https://github.com/EasyTier/EasyTier （官方 Release 有新版本） |
| 它能带来 | 把家里的机器、云服务器、手机组成一个虚拟内网，出门也能访问 |
| 不装会怎样 | 只在本机/局域网访问；公网访问需要另想办法 |

**LGPL-3.0 的含义（关键）**：

- ✅ 允许再分发二进制
- ⚠️ 但再分发时要履行义务：附**许可证全文**、保留**版权声明**、提供**获取对应源码的途径**
- ⚠️ 若你**修改**了它，修改部分必须以 LGPL 开源
- ✅ **只是以独立进程方式调用（不是链接进你的程序），你的主程序不必开源**

**所以：打包不是"侵权"，而是"接下一堆义务"。** 一旦你成了分发者，别人拿到的包出问题，找的是你。

## 三、真正该担心的不是版权，是密钥

这是很多人忽略的一点。这类组件的配置里通常含有**不该公开的东西**：

```ini
# 反面教材：如果你把服务配置原样打包，等同公开这些
--network-name  <你的网络名，常含姓名拼音>
--network-secret <你的组网密钥>
```

一旦进了公开仓库：

1. **搜索引擎和爬虫会索引**，删掉也留有历史与镜像
2. 别人可以加入你的虚拟内网，**你的机器就在他的网段里**
3. 撤销密钥需要所有节点重新配置，成本比想象高

**结论：任何含 `secret` / `token` / `key` / `password` 的配置文件，永远不进仓库。**
本项目已用 `.gitignore` 排除 `.env`、`data/`、`workspace/` 等运行时目录，但**不负责保护你在别处写的配置**。

> 如果你曾经把这类配置提交过，**请立即轮换密钥**，而不是只删提交。

## 四、推荐做法：声明依赖，不分发

### 4.1 仓库里只写「怎么装」，不放二进制

```bash
# dsh
npm install -g @deepseek-ai/dsh

# EasyTier（Linux，官方 Release）
# 到 https://github.com/EasyTier/EasyTier/releases 下载对应架构的包
# 也可以用它自己的安装脚本，注意脚本会以 root 运行，先看清楚内容
```

这样做的好处：

- 你不是分发者，**不承担 LGPL 的再分发义务**
- 使用者拿到的是官方最新版，安全更新不用你转发
- 仓库保持轻量（本项目全部代码不到 1 MB）

### 4.2 用容器「引用」而不是「复制」

如果你希望别人一条命令就能带上组网能力，**引用官方镜像**是干净的做法：

```yaml
# 示例片段：只作说明，实际使用请以官方镜像文档为准
services:
  easytier:
    image: easytier/easytier:latest
    restart: unless-stopped
    network_mode: host
    command: >
      -i 10.0.0.1
      --network-name ${ET_NET_NAME}
      --network-secret ${ET_NET_SECRET}
    environment:
      ET_NET_NAME: ${ET_NET_NAME}
      ET_NET_SECRET: ${ET_NET_SECRET}
```

要点：

- 镜像由上游维护，**分发者是镜像仓库，不是你**
- 网络名与密钥走环境变量，**由使用者自己填**，不写死在仓库里
- 使用者不配置就只是不启动这个容器，不影响主站

### 4.3 如果确实要打包（不推荐，但合法）

必须同时满足：

- [ ] 附 `LICENSE` 全文（LGPL-3.0），放在显眼位置
- [ ] 保留原始版权声明与版本号
- [ ] 明确写出「未做修改」或「修改了哪里」
- [ ] 提供获取对应源码的途径（未修改时指向官方仓库即可）
- [ ] **绝不打包任何配置文件、密钥、账号**
- [ ] 在 README 说明「本包内含第三方组件，各自遵循其许可证」

## 五、有没有更简单的替代方案

很多时候你并不需要这两个组件，替代方案反而更省事。

### 想让人从外网访问内网服务

| 方案 | 复杂度 | 适合谁 |
|---|---|---|
| 公网 IP + 端口映射（云服务器本身就有） | 低 | 有云服务器的人，**大多数场景这就够了** |
| Cloudflare Tunnel / frp | 低 | 没有公网 IP，需要临时暴露一个端口 |
| Tailscale | 低 | 想组私有网络，客户端体验好 |
| **EasyTier** | 中 | 想要完全自建、去中心化、可自控中继 |

**关键判断**：如果你的服务本来就跑在有公网 IP 的云服务器上，**根本不需要 EasyTier**——直接开端口或用反向代理即可。

### 想让 AI 能动手干活

| 方案 | 说明 |
|---|---|
| **dsh** | MIT，npm 一条命令，本项目的「与鱼」通道就是为它设计的 |
| 其他命令行 agent | 只要能接 OneBot 协议或提供 HTTP 接口，原则上都能替换 |
| 不做 | 只用聊天与棋牌，**这是绝大多数人的实际需求** |

## 六、一句话总结

- **不分发** → 零法律负担，仓库干净，别人按文档自己装
- **要分发** → 合法，但你要承担许可证义务、版本维护、安全更新
- **永远不要** → 把配置和密钥跟着一起打包

对「让别人快速复刻」这个目标来说，**一份写清楚安装步骤的文档，比塞一个 30 MB 的二进制有用得多**。
