# 和鱼一起玩的网站 · 部署与维护手册

> 性质：脱敏重写版，可对外分享。
> 读者：拿到网站框架、网站文件与本文档的部署者，以及协助部署与改造的通用 AI。
> 用途：从零部署、迁移复用、日常维护、二次改造。
> **口径声明**：本文档按**当前版本实测口径**撰写。网上流传的同类项目文档多为某时点的理想态记录，其中「记忆天然互通、无需打通」一类描述**不成立**，不得作为部署或改造依据。本文档不含任何具体环境值，所有环境相关量一律用占位符表示。
>
> **实施状态**：本文档描述的框架与四层记忆，代码在本仓库 `memory/` 目录中，可独立运行与自检。
> **作用范围**：记忆增强目前只接入了**聊天室与游戏内 AI 助手**（`/api/chat`）。
> 五子棋 AI 对手、万象牌 AI 队友、与鱼的命令执行能力，**本仓库不包含**，需要外部 agent 接入（详见第 2 章「能力边界」）。
> 第 14 章给出落地方式与验收判据，不含任何环境值。

## 1. 产品背景：为什么这么设计

> 给协助部署与改造的 AI：理解动机比照抄配置更重要。以下语义在改代码时不得破坏。

### 1.1 「一条鱼」

使用者养的是**一条**鱼：无论从聊天室、网站游戏、还是「与鱼」通道进入，面对的都是同一个角色——同一身份、同一份连续记忆、同一套当下约定。使用者不该因为换了个地方就重新提示。三个正交目标：**单一身份、连续记忆、跨通道一致**。

三通道分工：

| 通道 | 用途 | 硬约束 |
|---|---|---|
| 聊天室 | 日常闲聊 | 保持**更快更便宜** |
| 网站游戏 | 网页游戏与游戏内 AI 助手 | 游戏里发生的事也算共同经历 |
| 与鱼 | 聊天房间（文字/图片/文件）；**命令执行需外部 agent 桥接** | 若你自行接入 agent，其工具能力不得因统一身份被废弃 |

### 1.2 四层记忆

| 层 | 存什么 | 何时收缩 | 收缩成什么 | 使用者可见性 |
|---|---|---|---|---|
| **L1 临时** | 每手落子坐标、每张出牌、高频重复信息 | 局终或达条数阈值 | 该局「代表性＋特殊性」摘要 | 明细不可见，摘要可见 |
| **L2 近期** | 三通道全部最近往来 | 按时间窗口或条数 | 浓缩摘要（留结论与约定，丢原话） | 可见浓缩结果 |
| **L3 长期** | 浓缩后的事实，每条带时间 | 低频（远低于 L2） | 更短条目（合并／去重／过期） | 可见且带时间，可改可删 |
| **L4 适配器** | **怎么做事**：操作方式、打法偏好、临时指令 | 不参与收缩，按作用域失效 | 不收缩，只失效／撤销 | 可见（按作用域分组） |

规则：越往下「记得久但记得粗」；L1 明细不进 L3（人不会记住很久以前的固定安排）；L2／L3／L4 都要能被使用者看见并一句话改正。

### 1.2.1 压缩与裁剪：什么会丢、什么不会丢

> 这一节是改动代码时最容易踩坏的地方，务必先读。

| 环节 | 触发 | 做法 | 会不会丢信息 |
|---|---|---|---|
| L1 明细 | 每次动作 | 追加一条；明细**永不删除**，但注入时只看最近若干条 | 不丢，只是不注入 |
| L1 → L2 上浮 | 满条数阈值或局终 | 启发式提炼（特殊节点全留 + 每类取样本 + 频次统计），此环节仍零 LLM（低频离线，确定性优先） | 明细仍在，摘要入 L2 |
| L2 近期渲染 | 每次拼提示词 | 时间窗口 + 轮数上限 + 双写去重 + 噪声过滤 | 裁的是**本次注入**，文件不删 |
| **L2 → L3 浓缩** | 摘要沉淀满一定天数，由低频任务执行 | 清洗前缀与频次统计、保留结论与关键节点，写成带时间戳的长期事实 | 原摘要打标但**不删**，可追溯；同一条不重复浓缩 |
| **L3 久远压缩** | 节流周期（远长于 L2 裁剪）才检查一次 | 久远且属时效性内容的条目归档；稳定身份偏好永不因时间压缩 | 只改状态、**永不物理删除** |
| L4 适配器 | 动作成功 / 局终 / 用户撤销 | 按作用域失效 | 只归档，不删 |
| 注入总预算 | 超预算时 | **只裁近期与临时明细**；人设、长期事实、适配器一律不裁，裁光仍超就停手并标记降级 | 不丢 |

三条不可破坏的约束：

1. **人设与长期事实属于不可裁剪块**：即使把预算压到极小值也要全文保留。它们是身份与历史，丢一条就是「失忆」。
2. **浓缩不等于删除**：L2 浓缩成 L3 后，原摘要打标记、文件里仍在；L3 久远压缩只改状态。任何时刻都能回溯原始记录。
3. **长期层的改动频率必须远低于近期层**：近期每次渲染都裁，长期只在长节流周期检查一次，且带沉淀门槛，避免把昨天的闲聊立刻变成长期事实。

**长期事实不写回原长期记忆文件**：走旁路数据文件，注入时合并进长期块。这样既打通了「近期变长期」，又不会和既有的每日摘要任务抢同一个文件（改动前后该文件指纹须一致）。

### 1.3 时间戳：存与聊分离

- **存**：每条记忆内部带发生时间，记忆清单对使用者显示时间。
- **聊**：回复正文**默认不出现时间戳**；禁止句首／句尾附加日期，禁止每条消息带时间后缀。
- **只在三种情形明说时间**：使用者问「什么时候」；时间本身是事实内容；使用者要求列清单。
- **相对优先**：「上次」「前几天」优于绝对日期。
- 原因：模型会照抄注入上下文的格式，历史上出现过「加了时间戳后，机器人开始自报家门」的问题。因此必须把「存储格式」与「回复格式」彻底分开。

### 1.4 适配器：三档作用域

| 档 | 生效范围 | 失效触发 |
|---|---|---|
| `once` | 仅下一次决策 | 用完即删 |
| `session` | 本次会话／本局 | 局终自动结束 |
| `game` | 同类玩法跨局长期 | 需显式撤销，或被新偏好取代 |

**判定由模型裁决（`memory/llm.js`），脚本只做离线兜底。**

- 「是否该记 / 规则正文写什么 / 作用域多长 / 撤销哪条」全部由模型输出严格 JSON 决定；
  模型不可用时才走保守兜底（只认显式立约定词，一票否决拖延、反话、完成态陈述）。
- 下面这张词表优先级**只在离线兜底时生效**，不再是主判定逻辑：
- 「以后／每次」→ `game`
- 「这次／下一手／就这一下」→ `once`
- 描述当前局面危急（如「马上要连五了」）→ 局面锚点，落 `session`
- 默认 `session` 的理由：宁可少记（不长期跑偏），不可多记
- 缺有效 ctx（`game` / `sessionId`）的通道一律**不落库**：注入端只对 session 档校验 sid，
  改档位或补 sid 都会让错误规则真正进 prompt。详见 README「记忆的判断权」一节与 6 条验收判据。

**撤销**：任一通道一句话「这条不算了／以后别这样」即生效，无需指定作用域，回一句确认即可。
**体验要求：每步决策前都要重读当前有效的适配器**，不能只在开局读一次——这是「下一步真的不执行」的前提。

| 用例 | 使用者说 | 应识别为 | 应表现 | 不应出现 |
|---|---|---|---|---|
| 1 | 「你这样不对，先打给格挡的牌」 | `game` 长期偏好 | 之后各局都优先出防御类牌 | 下一局就忘 |
| 2 | 「你马上五子棋连接五子了，能不能给我一个机会别连」 | `session` 局面锚点 | 下一步真的不连 | 下一步仍连；或下一局还让 |

### 1.5 小鱼自己操作游戏

她在游戏里**自己决策、自己落子／出牌**，不是「脚本自动玩 + 读日志转述」。一局结束后要记得本局具体细节并能讨论。
**棋力／牌技水平是可选项，不是必需**：验收只判「是否自主决策、是否记得细节、是否遵守约定」，不判胜负与水平高低。

### 1.6 不可破坏清单

1. 三条通道必须是同一个角色；任一处学到的、改掉的，其余处同步生效。
2. 「与鱼」的工具能力不得因统一身份被拿掉。
3. 聊天室日常闲聊保持更快更便宜，重型处理只在「与鱼」发生。
4. 会话级约定**不因时间推移自动失效**，只因使用者明确结束、或被新约定取代而失效。
5. 使用者能看见并一句话纠正已记内容。
6. L1 明细不进长期层；回复正文不带时间戳。
7. 适配器每步重读；作用域失效按 1.4 执行。
8. 游戏动作由她在自己回合自主给出；不要改成脚本路径，也不要代使用者操作（除非另行明确授权）。

## 2. 现网实测口径（改造前必读，勿照抄历史文档）

### 2.1 三个游戏的动作入口与决策归属

| 游戏 | 动作入口 | 谁决策 | 规则层负责什么 |
|---|---|---|---|
| 五子棋 | `POST /api/go/move` | LLM 出坐标 | 规则仅兜底 |
| 万象牌 | `POST /api/action` | 战斗阶段由 LLM 决策 | setup／shop／reward 由规则处理 |
| 心有灵犀 | `POST /api/lx/submit` | LLM 决定词 | 「各写一个词、比对是否相同」制，**没有提问接口** |

### 2.2 结构与调用约束

- 站点入口文件在顶层直接 `listen`，**不能 `require`**（会二次占用端口）。
- 纯逻辑库（如 `engine.js`）可以 `require`。
- 五子棋跨进程唯一正规入口是 HTTP 接口，不要试图在同进程内直接改状态。
- 三个游戏场景在 bot 侧是**轮询拉状态**，不是推送；改造时不要按推送假设写。
- 历史文档里「记忆天然互通、没有打通动作」与现网实测冲突：**三通道记忆本不互通**，跨通道一致性必须显式实现。
- 四层记忆／适配器三档／小鱼自主操作／棋力非必需，一律以产品定义文档（PRD v2）为准，不引用历史理想态描述。

### 2.3 编号消歧（防止接错层）

历史资料里出现过两套都叫 L1/L2/L3 的分层，**含义不对应**，接手时务必按本节区分：

| 来源 | 编号 | 状态 |
|---|---|---|
| 产品定义（PRD v2，**唯一有效**） | L1 临时 / L2 近期 / L3 长期 / L4 适配器 | **采用** |
| 旧系统架构方案稿（v1 阶段，标为方案稿） | L1 会话约定 / L2 长期事实 / L3 近期事件 | **编号全部废止** |

- 旧稿的 L 编号**一律作废**，仅沿用 `contracts` / `facts` / `events` / `recent` 这类**块名语义**，且不与 v2 的 L 编号强绑定。
- 历史总记录里写的是**三层**记忆，**没有**适配器三档作用域（全库无先例），不要照抄其分层。
- 旧稿里的「适配器」指的是注入／运行侧的几个场景适配模块，与 v2 里「数据层的规则集合（可增删改、带作用域）」不是一回事：前者是**消费方**，后者是**数据源**。两者不合并、不互相覆盖命名。
- 判定原则：**四层定义看 PRD v2；块名与数据结构看实施代码；历史文档只作方法层参考。**

## 3. 三档部署路线

| 档 | 需要什么 | 改动面 | 成本 | 适用谁 |
|---|---|---|---|---|
| **A 最小可跑** | 静态站点 + 一个 LLM 接入 | 仅站点与模型配置，不接记忆 | 最低 | 先验证能打开、能陪聊 |
| **B 标准** | A + 四层记忆 + 适配器 + 三通道 | 加记忆层、通道对齐、可见与纠正入口 | 中 | 要「一条鱼」的完整体验 |
| **C 完整** | B + 游戏自主决策 + 局后复盘 | 再接三个动作接口、每步重读适配器、局后细节留存 | 中高 | 要小鱼自己下场玩 |

> 成本只作相对描述，实际取决于所选模型与调用频次。建议先按 A 档小流量验证，再逐档升级。

### 3.1 A 档 · 最小可跑
只放站点文件、配一个模型接入。能打开页面、能对话即可。**此档没有记忆**，必须在界面或说明里讲清楚，别让使用者以为已经是「一条鱼」。

### 3.2 B 档 · 标准
在 A 上补齐四层记忆、三通道身份对齐、适配器三档，并提供「看得见、一句话能改」的纠正入口。注意：**统一记忆会把一条错误事实同步到三条通道**，所以纠正入口必须与记忆层同时具备，不能后置。

### 3.3 C 档 · 完整
在 B 上接 2.1 的三个动作接口，让小鱼在自己回合自主给出动作；每步重读适配器；局终前记录结果，局后能复述具体细节。棋力水平不做要求。

## 4. 从零部署（通用步骤，全部占位符）

1. 准备运行时（Node 等），版本以满足依赖为准。
2. 把站点与服务文件放到 `<DEPLOY_ROOT>`。
3. 用环境变量提供 `<LLM_API_KEY>`、`<AUTH_TOKEN>` 等；常量走 `process.env.<NAME> || 默认值`。
4. 配置 `<HOST>`、`<PORT>`、`<LLM_PROXY_PORT>`、`<WS_PORT>`、`<PANEL_PORT>`，确保互不冲突。
5. 先跑纯逻辑自检，再启动站点入口（顶层 `listen` 只启动一次）。
6. 浏览器访问 `<HOST>:<PORT>` 验证页面；再验证模型接入能返回。
7. 按第 3 章选档接线，每接一层跑一次第 9 章自检。
8. 交付前过第 12 章自查清单。

## 5. 迁移与复用（换机／换环境）

- **备份优先**：改动前完整备份，并校验关键文件。
- 只搬「站点文件 + 配置模板 + 本文档」，**不搬任何含真实凭据或私人内容的历史记录**。
- 新环境重新生成所有凭据，不复用旧值。
- 逐项替换占位符；**同一条命令内多处路径必须一起替换**，否则复制即断。
- 按 A → B → C 顺序逐档验证，不要一次全接。
- 迁移后重复第 9 章自检与第 12 章自查。

---

## 6. 运维原则（方法层，已去除一切具体值）

1. 常量不硬编码，一律 `process.env.<NAME> || 默认值`。
2. 改前备份、改后自检；改动范围最小化。
3. 测试不得使用真实使用者身份；测试房间用完即清。
4. 不要 `require` 顶层 `listen` 的入口文件；纯逻辑库才可复用。
5. 注入给模型的上下文要清掉时间戳与元信息，防止模型照抄格式。
6. 对局结果必须在「重开之前」记录。
7. 状态与展示分离；展示层不反向写状态。
8. 轮询侧要有超时与幂等，不要假设推送。
9. 房间异常先查房间文件，再决定是否清空。
10. 分清「规则层」与「LLM 决策层」，不要互相替代。
11. 成本按调用频次监控；异常时先降级再排查。
12. 任何对外文档都先过脱敏清单。

## 7. 接口契约摘要

- 风格：统一 HTTP JSON 接口；房间以 `<ROOM_ID>` 标识。
- 三个游戏动作入口见 2.1。
- 通用约定：请求带房间与身份占位标识；响应返回最新状态；bot 侧轮询拉取。
- 跨进程改动一律走接口，不直接改内存状态。
- 自检顺序：纯逻辑 → 接口连通 → 决策归属 → 状态落盘 → 三通道一致性。

## 8. 玩法说明（脱敏）

- **五子棋**：对弈，落子以坐标提交，胜负由规则判定。
- **万象牌**：多层双人合作卡牌，含天赋经济与出牌策略；战斗阶段由 LLM 决策，准备／商店／结算由规则处理。
- **心有灵犀**：**各写一个词、比对是否相同**的猜词玩法，没有提问接口；由 LLM 决定写什么词。
- 通用：一局结束前记录结果；局后能复述本局具体细节。

## 9. 自检流程与事故清单

### 自检（每项都要过）

- [ ] 站点入口只启动一次，端口无冲突
- [ ] 模型接入能返回
- [ ] 三个动作接口按 2.1 的决策归属工作
- [ ] 三通道身份一致
- [ ] 记忆读写生效，使用者可见、可一句话纠正
- [ ] 适配器三步：识别档位 → 下一步生效 → 到点失效
- [ ] 局后能复述至少两个本局具体细节
- [ ] 回复正文无时间戳

### 事故清单（现象 → 定位 → 处置）

| 现象 | 定位 | 处置 |
|---|---|---|
| 房间有规则有先手但没人能动 | 房间状态残留 | 先查房间文件，确认后清空重进 |
| 状态重启后丢失 | 落盘调用缺失 | 补齐保存调用并验证重启后仍在 |
| 回复里出现时间戳或机器腔 | 模型照抄注入格式 | 清理注入上下文，加展示层兜底 |
| 上下文越来越长、变慢变贵 | 临时明细未收缩 | 按四层阈值上浮摘要、丢弃明细 |
| 约定隔天失效 | 用了固定时长过期 | 改为显式结束／被取代才失效 |
| 游戏动作不生效 | 走了非正规入口或改了规则层 | 回到 2.1 的 HTTP 入口 |

## 10. 常见改造路线与风险

| 想做的事 | 建议路线 | 主要风险 |
|---|---|---|
| 先能打开网站 | A | 误以为已「一条鱼」；A 档无记忆，需明示 |
| A → B | 补四层记忆 + 通道对齐 | 错误事实会被同步到三通道，必须同时提供可见与纠正入口 |
| B → C | 接三个动作接口 + 每步重读适配器 | 把规则层改成 LLM 决策会破坏玩法；不要改成脚本自动玩 |
| 轮询改推送 | 不建议单独改 | 三场景均按轮询假设实现，改一处会全链路失配 |
| 加时间戳 | 只加在存储与清单 | 直接加到注入上下文会让回复带上时间戳 |
| 提升棋力 | 可选项 | 影响成本与延迟；水平非验收项 |
| 换模型／换代理 | 先小流量 | 成本与延迟需重新建立基线 |

## 14. 实施落地说明与验收判据

> 本章说明「已经怎么落地、怎么确认它没坏」，全部为方法与判据，不含任何环境值。
> 若你是接手的通用 AI：先看本章确认当前状态，再按第 4 章从零部署或第 5 章迁移复用。

### 14.1 落地方式：只新增，不覆盖

| 类别 | 做法 |
|---|---|
| 四层数据 | 新增四个空骨架 JSON；长期层用**旁路元数据**保存时间戳与状态，不改原长期记忆文件一个字节 |
| 记忆模块 | `memory/` 下 8 个文件：常量、存储、渲染、适配器、接入层、浓缩任务、初始化、自检；零第三方依赖 |
| 接入 | 只在 6 个既有文件里做增量：人设入口、站点提示词、与鱼桥、三个游戏场景 |
| 回滚 | 每个接入文件改动前单独留一份副本；另有全量备份；设一个环境变量即可一键关闭增强 |

**不丢信息的三条结构性保证**：

1. 人设与长期事实属于「不可裁剪块」，不参与任何预算削减；即使预算给到极小值也全文保留。
2. 只有近期对话与局内明细可裁——这两层本来就设计成浓缩后上浮，重复与噪声可安全丢弃。
3. 所有失效都是状态标记归档，**永不物理删除**；改之前先备份，改完可逐文件比对还原。

### 14.2 必备验收用例（改完必跑）

| # | 用例 | 期望 |
|---|---|---|
| 1 | 立约定「每回合只能做一件事」→ 隔一段时间、换一局、零重申 | 规则仍生效；局终不自动失效 |
| 2 | 使用者说「这条不算了」 | 规则立即不再出现；旧条目归档保留可查 |
| 3 | 打法纠正「这样不对，先打防守牌」 | 判为跨局长期偏好 |
| 4 | 局面请求「马上要连成五子了，给个机会别连」 | 判为本局临时；下一局不再理会 |
| 5 | 「这局约定…」/「就这一手…」 | 分别判为本局 / 单次 |
| 6 | 同一句话被两个通道双写 | 近期记忆里只出现一次 |
| 7 | 渲染结果检查 | 含人设全文、含全部长期事实行、含时间表达规则、**不含裸日期串** |
| 8 | 四个通道分别渲染 | 都含同一份人设与长期事实 |
| 9 | 极小预算 | 人设与长期事实仍完整，不因预算被裁 |
| 10 | 模块缺失 / 文件损坏 | 各通道静默走原逻辑，进程不崩、网站可用 |
| 11 | 局终时由场景侧算好的结果摘要 | 原样保留并上浮到近期层，不能被内部统计覆盖或静默丢弃 |
| 12 | 无玩法上下文的通用通道读长期偏好 | 仍能看到绑定了具体玩法的长期偏好（同一条鱼） |
| 13 | 单次约定「就这一手…」 | 动作成功后才失效；动作失败要留到下一次，不能提前消费 |
| 14 | 读取规则后的缓存 | 查询条件不同不能命中同一份缓存；规则被消费后缓存必须失效 |
| 15 | 近期摘要沉淀够久后跑浓缩 | 生成一条带时间戳与来源的长期事实；记录里保留具体细节；再次运行不重复 |
| 16 | 浓缩后的事实 | 各通道都能读到同一条；已浓缩摘要不在近期层重复注入；原摘要文件里仍在 |
| 17 | 久远且属时效性的长期事实 | 低频检查时归档压缩；稳定身份偏好永不被压缩；归档条目仍可追溯 |
| 18 | 浓缩 / 压缩前后 | 原长期记忆文件指纹完全一致；预览模式不写任何文件；预算压到极小值仍不丢人设与长期事实 |
| 19 | 节流周期 | 周期未到时跳过久远压缩，不重复执行 |

### 14.3 上线顺序与冒烟

1. 先做全量备份，记录关键文件指纹。
2. 只上传新增模块，在目标环境跑自检，确认路径与依赖可读。
3. 再逐个替换接入文件，每个都留独立副本；替换后先跑语法检查。
4. 检查站点入口文件里带契约标记的补丁块数量是否守恒（历史事故：整文件重写导致补丁丢失）。
5. 按「站点 → 机器人 → 桥接」顺序重启，每步单独验证再进下一步。
6. 冒烟：逐个请求站点与主要页面入口，全部返回正常；查看进程日志无异常。
7. 初始化长期层元数据后，**复核原长期记忆文件指纹必须与改前一致**。
8. 最后复跑 14.2 全部用例。

### 14.4 本次实测结果

- 落地验收用例：全数通过；另有一组接入侧专项回归（局终摘要、跨通道长偏好、单次约定消费时机）全数通过。
- 浓缩链路专项回归全数通过；并做过一次端到端演练：一条久远的局终摘要被浓缩成长期事实后，「制胜五连位置」这类具体细节在聊天室与与鱼通道都能读到，原摘要仍可追溯，人设全文保留，注入内容无裸日期。
- 浓缩任务以低频定时任务运行，排在既有每日摘要之后、备份之前；首次以预览模式确认无意外写入后再正式启用。
- 站点主要入口：全部正常返回。
- 人设与长期事实：全文保留，长期事实逐行零丢失。
- 历史数据：原文件指纹与改前一致；流水账只追加、历史行原样保留。
- 进程与桥接：重启后全部在线，桥接正常连接。

> 换环境部署时结果可能不同，按 14.2／14.3 自行复跑，不要以本次结果代替验收。
