# 语音：让她带着情绪说话（以及为什么唱歌是另一回事）

> 这篇是「照着做能复刻出同样效果」的操作文档。它描述的是一条**跨三个进程**的链路：
> 站点（`server.js`）↔ dsh（`dsh web`）↔ 语音插件（`dsh-plugin-tts`）。
> 少任何一环，效果都会退化成「机械念白」。

---

## 1. 先说结论：效果由三件事决定

| 环节 | 用什么 | 决定什么 |
|---|---|---|
| 合成引擎 | **Breeze**（ElevenLabs 风格）或 **小米 MiMo**（OpenAI 风格） | 音色像不像人、有没有呼吸感 |
| 音色（voice_id） | Breeze 账号里的音色 id | 「这是谁在说话」——声音的人格 |
| 情绪（mood） | 工具参数 → 插件 `style` | 快/慢/软/沉，同一句话听起来是开心还是低落 |

三个都到位，才不是朗读。**只换引擎不换音色**，听起来只是换了个播音员。

---

## 2. 链路长什么样

```
她（dsh 里的模型）
  │  ① speak(text, mood, voice, sing?)
  ▼
integrations/dsh-tool-memory/lib/index.js   ← 本仓库里的插件
  │  ② POST http://10.144.144.1:3080/dsh-tts/speak   {text, style, voice, target:""}
  ▼
dsh-plugin-tts（第三方，不在本仓库）
  │  ③ 按 tts.apiStyle 选 Breeze / MiMo，拼各自的请求体
  ▼
上游 TTS  →  wav 落在 /root/.dsh/dsh-tts/voice/
  │  ④ 复制到 /root/qq-workspace/voice/（**必须**，见下）
  ▼
  │  ⑤ qq_send_voice(path)  →  OneBot  →  QQ
```

### 为什么非要「复制一份」

`qq_send_voice` 有路径围栏：只放行**插件媒体目录**（`mediaDir`，默认
`/root/.dsh/media/onebot`）和**会话工作区**（`workspacePath`，这里是 `/root/qq-workspace`）。
插件把音频写在自己的 `dsh-tts/voice/` 下——**不在白名单里**，直接把路径交出去会被拒：
`本地路径不在允许的媒体目录内`。

所以 `speak` 工具在返回前 `copyFileSync` 一份到工作区。这一步少了，合成 100% 成功、
发送 100% 失败，而且报错看起来像「发送坏了」，很容易查错方向。

## 3. 装什么

| 组件 | 是否在本仓库 | 说明 |
|---|---|---|
| `dsh-plugin-tts` | ❌ 第三方 | 合成引擎的宿主，提供 `/dsh-tts/*` 路由与 `tts_speak` 工具 |
| `integrations/dsh-tool-memory` | ✅ | 本仓库的 `speak` / `my_voice`，把情绪和嗓子包成模型能直接用的工具 |
| Breeze 账号 | ❌ | 拿 `apiKey` 与音色 id（`voc_*`） |
| 小米 MiMo 账号 | ❌ | **只有唱歌需要**，见第 6 节 |

装插件（概要，完整步骤看插件自己的 README）：

```bash
# 插件装到 dsh 的 profile 下，然后在 profile 的 cordis.patch.yml 里 insert
# 注意：patch 里必须带 "- insert:" 包装，直接写名字不会生效
dsh --profile web --dump-config | grep dsh-plugin-tts   # 确认真的加载了
```

**踩过的坑**：`package.json` 里的 `dsh.client.inject` 只能写本机真实存在的客户端包。
写成 `@deepseek-ai/dsh-client-ui-conversation`（这个版本没有）会让整个插件静默不加载。

## 4. 配置写在哪、怎么写

配置文件：`$DSH_HOME/dsh-tts/config.json`（本项目是 `/root/.dsh/dsh-tts/config.json`）。
插件**每次调用都重读这个文件**，改完不用重启。

两套协议各存一段，互不覆盖：

```jsonc
{
  "tts": {
    "apiStyle": "breeze",        // ← 当前生效的是哪家：breeze | openai
    "apiKey":  "",               // ← MiMo 的 key（唱歌要用它）
    "model":   "mimo-v2.5-tts",
    "singStyle": "唱歌",         // 唱歌固定这个风格词，别翻译成 sing
    "singAttempts": 5,           // 唱不出来时上游重试几次（1~6）
    "breeze": {
      "baseUrl": "https://api.breeze.blue/v1",
      "apiKey":  "…",            // ← Breeze 的 key
      "model":   "breeze-tts-2",
      "voice":   "voc_d7fhsuhdaptx",   // ← 默认音色 id
      "voices":  [ { "id": "voc_…", "name": "大肥鱼（破晓版）" } ]
    }
  }
}
```

**关键一点：`apiStyle` 决定 voice 写哪一段。** 同一个「音色」输入框，在 breeze 模式下写
`tts.breeze.voice`，在 openai 模式下写 `tts.voice`。切了模式再填，否则存进去的和你以为的不是一处
（这是我们实际踩过的坑：面板显示已保存，合成时还是老嗓子）。

### 不要手改文件的两种正规写法

```bash
# ① 站点设置面板（人用）：页面右上角设置 → 语音页
# ② 站点接口（脚本/AI 用）：回环调用免令牌，写盘是「临时文件 + rename」的原子替换
curl -s http://127.0.0.1:3000/api/settings/tts                    # 读（key 已打码）
curl -s -X POST http://127.0.0.1:3000/api/settings/tts \
     -H 'content-type: application/json' -d '{"voice":"voc_xxx"}'  # 改默认音色
```

`writeTtsConfig` 的两个约定，改代码时别破坏：
- **空字符串 = 这次不改**，不是清空。key 输入框只显示掩码，用户只改模型时不该把 key 抹掉。
- 要清空默认音色，得显式传 `{"voiceDefault": true}`。

## 5. 音色与模型从哪来

别让用户手抄 `voice_id`——会错字，而且错一个字符就是 401/400。

```bash
# 拉音色（POST，不是 GET；GET 会 405）
curl -s -X POST http://10.144.144.1:3080/dsh-tts/voices \
     -H 'content-type: application/json' \
     -d '{"apiStyle":"breeze","apiKey":"<key>"}'

# 拉模型
curl -s -X POST http://10.144.144.1:3080/dsh-tts/models \
     -H 'content-type: application/json' \
     -d '{"apiStyle":"breeze","apiKey":"<key>"}'
```

拿到后写进 `tts.breeze.voices`，页面的下拉框下次直接从配置渲染。
站点侧还有个代理 `POST /api/settings/tts/voices`，作用一样，额外做两件事：
带上传入的未保存 key、成功后落盘。

**额度**（决定你敢不敢让她天天说）：Breeze 免费档 400 credits/天，一个汉字算 2 credits，
也就是**一天大约 200 个汉字**。她一次说 30 字以内，一天十来句就到顶了；超了会 402/429，
`speak` 会自动退回本机 edge-tts，所以不会哑，但会「换回机器味」。

## 6. 情绪是怎么变成声音的

### 走 Breeze / MiMo 时

情绪作为 `style` 传给插件，插件按协议塞进各自的字段。
但 Breeze 的**风格是长在音色上的**（`voice_id` 自带语气），它没有独立的 style 参数——
插件因此把 style 清空，否则会把「（沉稳 稳定 优雅…）」当正文念出来。
换句话说：**Breeze 下换情绪 ≈ 换音色**，这是协议限制，不是 bug。

### 退回 edge-tts 时

这时情绪被翻译成三个物理参数（`integrations/dsh-tool-memory/lib/index.js` 的 `VOICE_STYLE`）：

| 情绪 | 音色 | 语速 | 音调 |
|---|---|---|---|
| 开心 | 晓伊 | +12% | +16Hz |
| 得意 | 晓伊 | +8% | +10Hz |
| 撒娇 | 晓晓 | −6% | +26Hz |
| 黏人 | 晓晓 | −3% | +18Hz |
| 低落 | 晓晓 | −18% | −16Hz |
| 累了 | 晓晓 | −22% | −10Hz |
| 生气 | 晓晓 | +6% | +2Hz |
| 有点醋 | 晓晓 | +2% | +7Hz |
| 平常 | 晓晓 | −2% | +3Hz |

同一句话、同一个模型，语速差 29% 就是「开心」和「低落」的区别（实测 2.83s vs 3.65s）。

**edge-tts 的坑**：负数参数必须用等号形式 `--rate=-18%`。写成 `--rate -18%` 会被 argparse
当成选项，报 `expected one argument`。

## 7. 唱歌：为什么「用不了」

这是被问得最多的一条，直接给结论：

> **Breeze 协议没有唱歌参数。插件里唱是硬编码走小米 MiMo 的**
> （`dsh-plugin-tts/lib/tts-lib.js` → `resolveRouteStyle()`：`if (sing) return 'openai'`）。
> MiMo 没填 key，唱歌就必然是 401，和你 Breeze 配得多好没有关系。

所以：

| 想要 | 需要什么 | 代价 |
|---|---|---|
| 说话（带情绪） | Breeze key + 音色 | 免费额度 400 credits/天 |
| **唱歌** | **MiMo key**（小米 TTS 目前限时免费） | 慢：10~90 秒；**上游是概率性的**，有时只念不唱，`singAttempts` 默认重试 5 次 |

两条路都是「文本进、音频出」，没有真正的旋律生成。
想要「有明确旋律」的歌声，只有三条路，都超出本仓库范围：

1. **MiMo 唱歌**：把歌词整段给它，靠上游模型自己「唱」，成败看运气。
2. **换真正的歌唱模型**（Seed-VC / GPT-SoVITS 那一类：分离人声 → 换音色 → 混回伴奏）：
   要几百 MB 内存和 GPU 级算力，2G 小机器扛不住。
3. **字级音高拼接**（每个字按音符时长和音高单独合成再拼）：一定「有旋律」，但像机器人，
   工程量不小，适合玩梗不适合日常。

`speak` 工具现在的做法是：**发现 MiMo 没 key 就直接说清楚，不让你等 20 秒再吃一个 401**；
真去唱但上游只念不唱时，如实回一句「没唱出来」，不假装唱了。

## 8. 常见故障对照表

| 现象 | 真正的原因 | 怎么办 |
|---|---|---|
| 401 / `Unauthorized` | 当前 `apiStyle` 那一段没 key，或 key 填到了另一段 | 看 `apiStyle`，再确认 key 在对应分支 |
| `Breeze 协议需要在「音色 / voice_id」里填一个音色 id` | `tts.breeze.voice` 是空串 | 拉音色、选一个、保存 |
| 401 但「说话正常，只有唱歌失败」 | 唱歌固定走 MiMo，MiMo 没 key | 见第 7 节 |
| 合成成功但发不出去 | 音频在 `dsh-tts/voice/`，不在发送白名单 | 复制到工作区（`speak` 已内置） |
| `连不上插件（ECONNREFUSED）` | dsh 只监听 `10.144.144.1:3080`，**不是** `127.0.0.1` | 用内网地址，或改 `DSH_TTS_SPEAK_URL` |
| `GET /dsh-tts/voices` 返回 405 | 这些路由只接受 POST | 用 POST，并带上 `apiStyle`/`apiKey` |
| 面板保存了但音色没变 | voice 写到了另一家那一段 | 见第 4 节「apiStyle 决定写哪段」 |
| 突然变回机器味 | Breeze 当天额度用完，自动退回 edge-tts | 明天再来，或换 MiMo |

## 9. 给她（模型）用的两个工具

`integrations/dsh-tool-memory` 注册的，不是插件自带的 `tts_speak`：

| 工具 | 作用 | 为什么需要 |
|---|---|---|
| `speak(text, mood, voice?, sing?)` | 合成一段语音，返回工作区里的路径 | 情绪 + 换嗓子 + 唱歌，一个入口 |
| `my_voice(voice?)` | 看现在用哪家/哪个音色/还能选哪些；传 id 就换默认 | 以前这些只存在设置面板里，模型只能猜 id |

设计上的两个取舍：

- **失败必须有声**：插件挂了/没 key/超时，`speak` 一律退回 edge-tts。
  宁可机器味，也不要「她突然不说话了」。
- **唱歌失败不退回**：念白冒充唱歌更尴尬，所以唱歌失败就直说。

### 还得写进她的人设

工具会注册，但她不一定会用。`workspace/AGENTS.md` 里要有一段告诉她这套东西存在，
否则她会绕过工具去翻配置文件、翻插件源码——**这就是「她要找一会儿才找到接口」的真正原因**：
文档里只写了旧的 `say.py`，新的 Breeze 链路一个字都没有。

最小可用的一段（照抄改改就行）：

```markdown
## 说话（真发语音）

首选 `speak` 工具：`speak(text, mood)` → 拿到路径 → `qq_send_voice(path)`。两步都要做。
想换嗓子用 `my_voice`，不用问我，也不用去设置面板点。
sing=true 才是唱，唱歌只能走小米 MiMo，没填 key 时工具会直说。
`say.py` 只当插件彻底挂了的兜底。
```

`workspace/AGENTS.md` 每次会话都会注入，写在这里等于写在她的说明书上；
写在 `docs/` 里她看不见。

## 10. 安全

- key 在接口里**永远打码**（`sk-…abcd`），页面输入框留空表示「不改」。
- 写配置是「临时文件 + rename」，避免写一半断电留下半个 JSON（半个 JSON = 插件读不出配置 = 全部静音）。
- `/api/settings/tts` 是破坏性接口，走站点统一的 `guardAdmin`：
  设了 `AUTH_TOKEN` 就要令牌，没设则**只允许回环地址**。别把它暴露到公网。
