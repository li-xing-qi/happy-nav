# 和鱼的快乐导航

> 一个自带 AI 伙伴的网页导航站：聊天室、万象牌、五子棋、心有灵犀、与鱼。
> 站点本体零第三方依赖、纯 Node 内置模块、装好 Node 就能跑；AI 陪玩另需 `npm install`（只有一个 `ws`）。

一句话说明它是什么：**你部署一个网站，站里有一个能聊天、有记忆的 AI 小伙伴，还有四个可以自己玩或联机的页面。**

> **从零部署，或者直接把仓库丢给 AI 让它帮你装？** 看 **[DEPLOY.md](DEPLOY.md)**。
> 它按「先问五个问题 → 选档位 → 逐档操作 → 验收 → 坑清单」写，含 2 核 2G 小机器的实测内存账、swap、启动顺序、以及这套东西**还没做好**的地方（免得白折腾）。

## 先说清楚：哪些是自带的，哪些要你自己接

这个仓库包含**站点 + AI 陪玩（agent-bot）+ 与鱼桥接**三部分。**不包含**的只有两个第三方软件：dsh（让 AI 能跑命令）与 EasyTier（异地组网）。所以：

| 能力 | 开箱可用？ | 说明 |
|---|---|---|
| 五个页面 + 双人对弈 + 联机房间 | ✅ 是 | 不配任何密钥就能玩 |
| 聊天室 AI 对话 | ⚠️ 要配模型 | 填 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 即可，任何 OpenAI 兼容接口都行 |
| AI 画图 | ⚠️ 要装浏览器 | 需要 `puppeteer-core` + 一个 Chromium/Chrome；不装只是不能画图，聊天棋牌不受影响 |
| 四层记忆（人设/近期/长期/偏好） | ⚠️ 要配模型 | 已内置在 `memory/`，作用于聊天室与游戏内 AI 助手 |
| 好感度 / 心情 | ✅ 是 | 纯本地状态，不额外调模型；每轮给她三行（数值 + 规则），分数不上界面 |
| 状态栏（说话中 / 巡视领地中） | ✅ 是 | 与鱼房间的对方状态由桥接上报，45 秒有效 |
| 五子棋 AI 对手 | ✅ 是 | 仓库内 `agent-bot/` 提供，启动后它自己读局面、自己落子 |
| 万象牌 AI 队友 | ✅ 是 | 同上，`agent-bot/` 里包含卡牌队友场景 |
| 与鱼「跑命令 / 改文件 / 画图」 | ⚠️ 要接 dsh | 房间与桥接都在仓库里，但「干活」需要外部 dsh（见 `docs/接入dsh.md`） |
| 语音朗读 | ⚠️ 默认关闭 | 开启后走微软在线 TTS，朗读文本会离开本机 |
| 手机 App（安卓壳） | ✅ 可选 | 21KB WebView 壳，无广告无开屏；只连你自己的地址，见 [`clients/android`](clients/android/README.md) |

**一句话**：只跑站点，它是一个干净的双人聊天室 + 棋牌室；把 `agent-bot/` 也启动起来，四个场景就有了 AI 陪玩；再接上 dsh，与鱼才会「干活」。

### 关于第三方组件：本项目不包含、也不分发

想复刻「AI 能跑命令、能异地访问」这类效果时，会用到两个独立软件。它们**不是本项目的代码**，本仓库不打包它们：

|---|---|---|---|

| EasyTier | **LGPL-3.0** | 把多台机器组成虚拟内网 | 只在本机/局域网可用 |

安装方式、许可证义务、以及「什么时候其实不需要它们」，见 **[docs/可选组件.md](docs/可选组件.md)**。
想把 dsh 真正接到「与鱼」里（让它能跑命令、改文件、画图），按
**[docs/接入dsh.md](docs/接入dsh.md)** 操作，仓库里附带可直接运行的桥接脚本 `bridge/`。

**为什么不在仓库里塞二进制**：一是打包别人软件会让自己变成「再分发者」，要承担许可证义务与安全更新责任；二是这类组件的配置里通常含网络名与密钥，**跟着打包等于公开你的内网入口**。

## 三十秒跑起来

选一种就行。

### 方式一：Docker（最省事，推荐）

```bash
git clone https://github.com/li-xing-qi/happy-nav.git
cd happy-nav
docker compose up -d
```

打开 `http://localhost:3000` 即可。数据落在当前目录的 `data/` 与 `workspace/`，删容器不丢。

### 方式二：一条命令（Linux / macOS，有 Node 就行）

```bash
git clone https://github.com/li-xing-qi/happy-nav.git
cd happy-nav
bash deploy.sh
```

脚本会自动检查 Node 版本、建目录、生成配置、做语法自检，然后启动。后台跑用 `bash deploy.sh --daemon`，停止用 `bash deploy.sh --stop`。

### 方式三：Windows 双击

1. 装 [Node.js 18+](https://nodejs.org/)
2. 下载本仓库（`Code` → `Download ZIP`）并解压
3. 右键 `start.ps1` → 「使用 PowerShell 运行」

脚本会做和上面一样的检查与启动。

### 方式四：手动三步

```bash
npm start
# 或者
node server.js
```

**环境要求**：Node 18 或更高。**站点本体**不需要数据库、不需要构建、不需要 `npm install`。
**AI 陪玩（`agent-bot/`）需要一次 `npm install`**：必需依赖只有 `ws`，想画图再加 `puppeteer-core`。

## 部署完先做什么

1. 打开 `http://localhost:3000`，六个页面都能点开。首次启动会自动生成 `workspace/AGENTS.md`（人设）与 `workspace/MEMORY.md`（长期记忆）
2. **想启用 AI 对话**：复制 `.env.example` 为 `.env`，填入你的模型服务地址与密钥（任何 OpenAI 兼容接口都行），重启服务
3. **想改 AI 的性格和称呼**：编辑 `workspace/AGENTS.md`，保存即生效
4. **想让它记住你**：两种都行 —— 在聊天室说「记住：……」，`agent-bot` 会立即写进 `workspace/MEMORY.md`；也可以直接编辑那个文件（一行一条）。
   注：模型自身没有写文件的能力，写入是代码在收到「记住」后执行的，所以它不会自己乱改记忆。

> 没填 AI 密钥也能跑：站点、牌局、棋局都正常，只是没有 AI 陪聊与出招。

## 启动 AI 陪玩：agent-bot

站点只负责「页面 + 玩法 + 房间」。真正让四个场景有 AI 的是另一个进程：`agent-bot/`。

```bash
cd agent-bot
npm install          # 必需依赖只有一个 ws
# 想让 AI 能画图，再多两步（不装也不影响聊天与棋牌）：
#   npm install puppeteer-core
#   装一个 Chromium/Chrome，或用 CHROME_BIN 指向已有的可执行文件
cd ..
# 确保 .env 里模型配置正确，然后启动
cd agent-bot && node index.js
```

它会同时跑四个场景（聊天室陪聊、卡牌队友、五子棋对手、心有灵犀），共用同一份人设与记忆。
只想开其中一个：

```bash
NO_CARD=1 NO_GOMOKU=1 NO_LINGXI=1 node index.js   # 只开聊天室
```

**它做了什么**（对应源码位置，方便你改）：

| 场景 | 文件 | 行为 |
|---|---|---|
| 聊天室陪聊 | `scenes/chat.js` | 轮询房间新消息 → 带人设与记忆调模型 → 回复（可发表情包、可画图） |
| 卡牌队友 | `scenes/card.js` | 战斗阶段自己选牌，商店/奖励按规则走 |
| 五子棋 | `scenes/gomoku.js` | 自己读棋盘、自己判断落点，非法才用规则兜底 |
| 心有灵犀 | `scenes/lingxi.js` | 按需进出房间，自己决定写什么词 |

**记忆是怎么被写进去的**（这是它和站点的分工）：

| 触发 | 调用 |
|---|---|
| 与鱼里说「约定：…」「这条不算了」 | 桥接 → `handleCommand()` |
| 五子棋每落一子 / 卡牌每出一牌 | `noteStep()` 记进临时记忆 |
| 一局结束 | `endMemorySession()` 归档并提炼上浮 |
| 聊天室说「记住：…」 | 直接追加到长期记忆（立即生效，不等摘要） |
| 定时浓缩 | `node memory/compact.js`（建议挂 crontab，每天一次） |

> 已知缺口（原版就有的遗留问题）：卡牌场景没有明确的「局终」信号，所以它不会触发局终归档；聊天室场景也不处理「约定」类指令（只在与鱼与游戏场景生效）。这两处要补的话，位置分别在 `scenes/card.js` 与 `scenes/chat.js` 的消息处理入口。

## 记忆的判断权：模型裁决，脚本落盘

以前「是否该记 / 记成什么 / 作用域多长 / 撤销哪条」全靠词表 `includes` 和字符串截取，于是随口一句「这局打不过，以后再说吧」会被写成规则「再说吧」。现在这些**语义判断交给模型**，脚本只负责候选召回、写入、归档、裁剪这些确定性工作。

| 环节 | 谁决定 |
|---|---|
| 是否是约定 / 是不是拖延、反话、完成态陈述 | **模型**（输出严格 JSON，带置信度） |
| 规则正文写什么（由模型重写，不再 slice 原话） | **模型** |
| 作用域 once / session / game | **模型** |
| 撤销哪一条（必须给 id，不猜、不批量） | **模型 + 用户确认** |
| 原子写入、只归档不删除、去重、预算裁剪、降级 | 脚本 |

**两个写入通道**（同一套守卫，不同的触发方式）：

| 通道 | 谁发起 | 额外模型调用 |
|---|---|---|
| **工具通道**（默认） | 回复模型自己调 `save_rule` / `remember_fact` / `list_rules` / `revoke_rule` / `feel` | **不要**，判断和回复在同一次调用里 |
| **旁路裁决** | `handleCommand()`：转发消息前单独问一次模型 | 要（已有廉价召回预筛，闲聊不触发） |

工具通道把「确认」和「真的写了」合成一件事：工具返回「未记录：这句是放弃 / 拖延，不构成约定」时，模型当场改口，不会嘴上说「记下了」实际什么都没写。

**各通道能力**（`✅` 已接通，`—` 该通道不存在此能力）：

| 通道 | 写长期事实 | 写约定 | 约定生效 |
|---|---|---|---|
| 聊天室 `agent-bot/scenes/chat.js` | ✅ 工具 + `记住：` 兜底 | ✅ 工具 | ✅ 每轮注入 |
| 五子棋 `scenes/gomoku.js` | ✅ 工具 | ✅ 工具 | ✅ `adapterPrompt` |
| 万象牌 `scenes/card.js` | ✅ 工具 | ✅ 工具 | ✅ `adapterPrompt` |
| 与鱼 `agent-bot/yufish.js` → dsh | ✅ 工具（`integrations/dsh-tool-memory`） | ✅ 工具 | ✅ `renderFor('yu')` |
| 站点 `/api/chat` | — | — | ✅ `renderFor('api-chat')` |

> 与鱼回复由 dsh 生成，写入靠 `integrations/dsh-tool-memory` 这个 dsh 插件把同一批工具交给它；不装插件时退化为「桥接旁路裁决」（每条疑似指令多一次模型调用）。桥接本身只负责注入，不再负责落库——两处都写会重复。

**两道防线，缺一不可**（止血 ≠ 根治）：

- **止血**：缺有效 ctx（`game` / `sessionId`）的通道一律**不落库**。为什么不「改 scope / 降级 once / 补齐 sid」——注入端只对 session 档校验 sid，改成 once 或 game 反而会让错误规则立刻进 prompt 生效；game 档更糟，会永久生效。任何让规则变可见的止血动作都会把未修的语义误判暴露到决策链。
- **根治**：AI 语义门槛覆盖**所有写入入口**（与鱼桥、`记住：…` 直写长期记忆的旁路），并配可见/审计路径。

**没配模型时**：自动走保守兜底——只认显式立约定词，一票否决拖延/完成态/元语言否定，宁可少记不可错记。网站照常可用，`FOUR_LAYER=0` 仍可一键关闭。

查看与精确撤销：

```bash
node memory/audit.js list                  # 列出生效约定（含 id）
node memory/audit.js all                   # 含已归档
node memory/audit.js revoke <id>           # 按 id 精确撤销
node memory/audit.js archive-ghosts        # 归档存量幽灵规则
node memory/audit.js llm                   # 查看裁决器状态
node memory/verify-semantic.js            # 跑 38 项语义验收
node agent-bot/verify-tools.js            # 跑 30 项工具通道验收
```

> 「这条不算了」不再批量清空当前作用域。未点名时会列出候选让你指定，一条都不动——以前它会把你真正在用的长期偏好一起归档，还回一句「好，那条不算了」。

### 验收判据（顺序不能换）

改这块代码后必须跑 `node memory/verify-semantic.js`，判据如下：

1. `readAdapters()` 中不存在 `text==='再说吧'` 的 active 记录，且总条数不增 —— **第一道门槛，必须最先判**。只看注入侧会把「完全没修」误判为已修，因为幽灵规则的定义就是「写入但不注入」。
2. `handleCommand()` 返回空串，且不含「这局听你的」「记下了，以后都这样」「这步听你的」等肯定确认语。
3. `activeAdapters(ctx) === []`。
4. `adapterPrompt(ctx)` 不含「再说吧」。
5. `pendingOnceIds(ctx)` 为空。
6. 存量 active 规则可列出、可按 id 精确撤销，`rule:''` 不再触发批量撤销。

回归基线还覆盖：3 个 ctx（game / 与鱼 / api-chat）、4 个反例、幽灵规则归档、模型重写 `rule`、模型不可达时降级且正常约定仍可写入。

## AI 伙伴：四层记忆是怎么工作的

它不是一个「每次对话都从零开始」的聊天机器人。记忆分四层，越往下越久、越粗：

| 层 | 存什么 | 什么时候压缩 |
|---|---|---|
| **临时** | 这一局里每一步动作 | 满一定条数或一局结束时，提炼成摘要上浮 |
| **近期** | 最近几天的全部往来 | 渲染时按时间窗口与条数裁剪（只裁注入内容，文件不删） |
| **长期** | 浓缩后的事实，每条带时间 | 沉淀足够久才浓缩成长期；更久远的时效性内容低频归档 |
| **适配器** | 「怎么做事」的规矩与偏好 | 不按体积压缩，按作用域失效（单次 / 本局 / 长期） |

三条硬规则：

1. **人设与长期事实永不被裁剪**——预算是给人设和历史让路的，不是反过来。
2. **压缩不等于删除**——被浓缩、被归档的记录都还在文件里，可追溯。
3. **长期层改动频率远低于近期层**——不会把昨天的闲聊立刻变成长期事实。

细节见 [`docs/部署与维护手册.md`](docs/部署与维护手册.md) 第 1 章。

## 好感度与心情：数值给她看，判断也给她

不是「脚本按词表加减分」。那样每个人养出来的她都会一模一样——同一句玩笑在两种关系里分量差很远，脚本没法知道。

现在每次对话都会把**当前状态**一起给她（12 行，不带历史）。她记两样东西，尺度不一样：

| 层 | 尺度 | 怎么变 | 存在哪 |
|---|---|---|---|
| 亲密度 0~100（十档） | 几周到几个月 | 她觉得该变的时候调 `feel` | `mood.json` 的 `affinity` |
| 心情（8 个固定标签） | 几个小时 | 同一次 `feel` 调用里顺手报上来 | `mood.json` 的 `mood` |

为什么拆两层：只有亲密度的时候，70 分和 72 分她说的话一模一样，看起来不像有情绪的人，像在读一张配置表。心情 6 小时自动过期回「平静」（读的时候判断，写盘时把过期值落成「平静」），所以早上的撒娇不会留到晚上。

心情只用这 8 个词（写死成枚举，页面和日志才能渲染成标签）：

```
开心 / 黏人 / 撒娇 / 有点醋 / 低落 / 累了 / 得意 / 平静
```

注入的样子（12 行，一条路径一行）：

```
【亲密度 61/100（亲近）· 心情：平静 · 今天他：陪你聊了 3 次、叫了你 2 次昵称】
能让你心里动一下的（不用等大事）：动一下就调 feel 记下来，顺手标是哪一类；同一条路别每次都用同一种反应，也别每句都提「你今天…」。
· 陪着：一起待着、闲聊、各干各的 → +1~2，放松下来，话变多
· 报备：他讲自己在干嘛、去了哪、吃什么 → +1~2，接一句，顺口问一句
· 昵称：叫你昵称、给你起外号 → +2~3，应一声，或者假装嫌肉麻
· 想你：说想你、舍不得挂 → +3~5，害羞、回一句撩的、装没听懂，轮着来
· 暧昧：撩你、夸你好看可爱、语气往亲昵上贴 → +3~5，可以接、可以躲、可以反撩
· 被需要：找你商量事、跟你倾诉、让你陪着 → +2~4，认真听，给一句实在的
· 一起玩：下棋打牌、一起看东西 → +1~3，赢了得意，输了不服
· 记得：他记得你说过的事、提起旧细节 → +2~4，明显高兴，别装淡定
· 反向：敷衍（只回嗯、哦、一个表情）、失联（很久不来又不解释）、凶（骂你、不耐烦）、越界（玩笑开过头、不尊重你）、工具化（只在要东西时找你） → -2~-6，话变短、不主动，但不阴阳怪气
你和他亲近：说话自然熟稔，可以开玩笑，也可以小小地闹他一下。（底线：分数不要念出来；不阴阳怪气、不翻旧账、不威胁、不因为亲密度低就报复。）
```

第 13 行是**条件出现**的：连着 6 轮没记心情，才会追加一句「你们已经聊了 N 轮，你一直没记心情——这一轮先判断一次再说话」。这个计数每次注入提示词 +1（进程内最多每 60 秒 +1，免得同一条消息被注入多次把计数刷爆），`feel` 成功后清零。

### 路径表：她心里会动一下的东西

这一层不是「加分表」，是**她会在意的那些事**，一条一条分开，每条带自己的反应。原因很实际：旧版把十几种情况压成一句「被夸、被照顾、陪你聊天、说晚安…都算升」，模型读完只知道「这些加分」，不知道该有什么反应，结果她还是只有一个笼统的「热情度」。分成路径之后，「叫昵称」和「说想你」是两种不同的反应。

| 路径 | 什么算 | 建议分 | 她怎么反应 |
|---|---|---|---|
| 陪着 | 一起待着、闲聊、各干各的 | +1~2 | 放松下来，话变多 |
| 报备 | 他讲自己在干嘛、去了哪、吃什么 | +1~2 | 接一句，顺口问一句 |
| 昵称 | 叫你昵称、给你起外号 | +2~3 | 应一声，或者假装嫌肉麻 |
| 想你 | 说想你、舍不得挂 | +3~5 | 害羞、回一句撩的、装没听懂，轮着来 |
| 暧昧 | 撩你、夸你好看可爱、语气往亲昵上贴 | +3~5 | 可以接、可以躲、可以反撩 |
| 被需要 | 找你商量事、跟你倾诉、让你陪着 | +2~4 | 认真听，给一句实在的 |
| 一起玩 | 下棋打牌、一起看东西 | +1~3 | 赢了得意，输了不服 |
| 记得 | 他记得你说过的事、提起旧细节 | +2~4 | 明显高兴，别装淡定 |
| 敷衍 | 只回嗯、哦、一个表情 | -2~-4 | 话变短，不主动找话 |
| 失联 | 很久不来又不解释 | -3~-6 | 不追问，自己找事做 |
| 凶 | 骂你、不耐烦 | -4~-8 | 收着回，不辩解 |
| 越界 | 玩笑开过头、不尊重你 | -3~-6 | 直接说不喜欢，然后少说 |
| 工具化 | 只在要东西时找你 | -2~-4 | 只答不帮，不主动贴 |

「建议分」只是给她一个参照量级，**脚本不据此算分**——分数最终还是她的判断。反应一栏必须是能听见、看得见的行为（「话变多」「假装嫌肉麻」），不是「更亲密」这种形容词，否则她又会退回一个笼统的热情度。

### 今天的账：她记住的是细节

头行里那句 `今天他：陪你聊了 3 次、叫了你 2 次昵称` 来自 `log` 里最近 24 小时的 `kind` 统计：

- 只统计带 `kind` 的记录（老记录没有 `kind`，不产生条目）
- 最多报 4 类，按次数降序，量词统一「次」
- 一条都没有就整段省略，不留空括号

为什么这是重点：只有分数的时候，她最多说「你今天对我挺好的」。有了这句细账，她才能说出「你今天都叫我三次小傻鱼了」——拟人的关键是这种具体细节，不是数值高低。

`feel` 的参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `delta` | ✅ | -12 ~ 12 的整数，正数更亲近 |
| `why` | | 一句话理由，存档只留 24 字，不存聊天原文 |
| `mood` | | 心情，取值见上面 8 个词；6 小时内有效，不传就沿用一个 |
| `kind` | | 走的是哪条路径，取上面路径表的 key（`陪着`…`工具化`）。**只进日志和「今天的账」，不参与算分**；不在表里的值也原样记下来，只是统计不到 |

`mood` / `kind` 都是可选的，老的 `feel(6, '理由')` 两参调用照旧可用（`verify-tools.js` 和 dsh 插件都在这么调）。

脚本只做三件模型做不了的事：

| 脚本负责 | 为什么必须是脚本 |
|---|---|
| 存盘（原子写，失败静默） | 写不进去也不能影响对话 |
| 边界（0~100、单次 ±12；≥93 时正向收力、≤7 时负向收力） | 防止一句话从 55 拉到 100，或者一次清零 |
| 回落（每 12 小时 1 点，单次最多 2 点，落点见下） | 一次吵架不该永久生效 |

**回落是「软锚」，不是固定往 55 拉**。落点 = `max(55, 近 24 小时最高值 - 6)`：

- 高于落点 → 每 12 小时降 1 点，单次最多降 2 点
- 低于 55 → 慢慢往 55 回升（吵崩了也有回头的机会）
- 夹在 55 和落点之间 → 不动

之所以改：旧版固定往 55 拉、每 8 小时 1 点、单次最多 3 点，涨到 80 分的人只要两天不聊就被拽回「还算熟」，用户说的「好感太严苛」主要来自这里。人的关系不会因为两天没聊天就退回陌生人。

**「听不听指挥」也交给她**：五子棋里你说「让我一步」，提示词只告诉她「按你现在的亲密度自己决定答不答应」——亲密度低的时候她可以不答应，但规则里明确写了：不许阴阳怪气、不许翻旧账、不许编「规则不允许」这种借口。

她调不调、调多少，取决于你怎么养。这一层本来就该是她的判断，不是我的 `+5 / -7`。

**哪些场景参与**：

| 场景 | 每轮注入 | `feel` 工具 |
|---|---|---|
| 聊天室 / 五子棋 / 万象牌 | ✅ | ✅ |
| 与鱼（dsh） | ✅（单独一块 system-reminder） | ✅ |
| 心有灵犀 | — | — |

心有灵犀不参与，因为它每轮只让模型回**一个词**（`maxTokens: 20`），塞三行心情进去既没地方放也没有工具循环。这是有意留白，不是漏了。

### 页面上看得见，但不给分数

与鱼页面左侧栏多了一块「小鱼现在」，只显示一个**档位词** + 一句最近的原因（鼠标停上去也有）：

```
● 亲近
  刚因为「他说跟我聊天很开心」
```

十档，从冷到热。**每一档都有一句具体说法**（`mood.toneOf(band)` 出这段话，直接进提示词）：

| 分数 | 档位词 | 她大概怎么说话 |
|---|---|---|
| ≥92 | 黏糊糊 | 主动贴上去，用叠词和昵称，会撒娇要关注；但别每句都腻 |
| 84–91 | 很亲近 | 主动找话题，会问他在干嘛，偶尔撒个娇 |
| 74–83 | 挺黏人 | 愿意先开口，记着他说过的小事，语气偏软 |
| 64–73 | 亲近 | 自然熟稔，可以开玩笑，可以小小地闹他一下 |
| 54–63 | 还算熟 | 礼貌但不冷淡，愿意接话，但不主动贴上去 |
| 44–53 | 平常 | 客气、简短，接得住话，但不主动延伸话题 |
| 34–43 | 客气 | 话短，少主动，不撒娇 |
| 24–33 | 有点疏 | 回答偏短，不接玩笑，也不解释为什么短 |
| 12–23 | 冷淡 | 只回应必要的，不主动开口，但不阴阳怪气 |
| <12 | 冷透了 | 极简回一句，不主动，不阴阳怪气，也不威胁 |

以前中间五档（44~84）写的是「语气自然就行，不用刻意表现情绪」——那句话把整段关系抹平成了同一个语气，这也是「不够拟人」的来源之一。现在一档一句，中间不留「都一样」的档。

**数字不显示**，只在 `workspace/data/mood.json` 里。原因很实际：一显示分数，注意力就从「她今天什么脾气」变成「怎么把她刷到 80」，那味道就没了。档位词是从文件里读的（`band` 字段由 agent-bot 写），站点只读不判断，阈值不会存在两份。

存档只留最近 20 条变化，理由截 24 字，不存聊天原文。删了就是从 55（还算熟）重新开始。

### 这一版为什么改（`feel` 一度是 0 次）

线上日志统计里，工具调用 `draw` 15 次、`qq_send_image` 11 次、`search_chatlog` 6 次，而 `feel` **一次都没有**；`mood.json` 里只有与鱼（dsh 插件）产生的两条记录。工具确实挂在聊天室 / 五子棋 / 万象牌的 `ctx` 上，是模型从来不调。三个原因：

1. **工具轮 token 被掐死**：五子棋 / 万象牌传 `maxTokens: 100`（正文要短），这个 100 也被用在了工具轮上，模型刚写完 `tool_calls` 就没有额度写正文，于是学会了「别调工具」。现在工具轮给 `Math.max(maxTokens, 400)`，收尾那一轮仍用原始值。
2. **提示词位置太靠后**：与鱼把心情块单独放进紧贴本轮消息的 `<system-reminder>` 里所以生效；聊天室把它放在几百行 system prompt 的第 3 段，被后面的工具说明淹没。现在三个场景都紧跟 `persona()` 之后。
3. **提示词自己在劝退**：旧文案「一次一般 ±3~8」「觉得该变就调」，工具描述里还写着「觉得没什么可变的就别调」。现在改成「日常陪着聊也算、不用等大事」，并把日常陪伴 / 说晚安 / 叫昵称 / 分享日常 / 说想你这些正向方向明确写进清单。

4. **一句话罗列 = 只有一个热情度**（第二次改）：修完上面三条之后，第 2 行还是把十几种情况压成一句「被夸、被照顾、陪你聊天、说晚安…都算升」。模型读到的是「这些加分」，读不到「这些是彼此不同的事、该有不同反应」。现在拆成 13 条路径、一条一行、每条带自己的反应（见上面「路径表」），并把「今天他做了什么」统计进头行。

**只做到「提示词与机制层面修好」**：这几条改的是「为什么它不该调」「调了会不会被 token 掐死」「调的时候分不分得清是哪条路」。真机效果要看之后几天日志里 `feel` 的调用次数、`kind` 的分布和 `mood.json` 的实际变化，现在还不下结论。

验收：`node agent-bot/verify-mood.js`（75 项：钳制、软锚回落、心情过期、十档语气、路径表、今天的账、清单式提示块、kind 容错、催记心情、场景覆盖）。

## 状态栏：她现在在干嘛

以前与鱼页面的对方状态只有「在线 / 暂时离开」，因为房间只知道 `lastSeen`。现在多了一个 `act`：

| 状态 | 什么时候 |
|---|---|
| `思考中` | 桥接收到你的消息，还没开始回 |
| `巡视领地中` | 消息里提到服务器 / 日志 / 部署 / 备份这类事（她接下来要动手） |
| `说话中` | 正在往房间发消息（发图也算） |
| `发呆中` / `打盹中` | 90 秒没动静（0–7 点叫打盹） |

规则：**45 秒内有效**，过期自动回到「在线」，不会卡在「思考中」；上报走 `POST /api/yu/act`，失败静默——状态是装饰，绝不能挡住消息。

这个接口是通用的：定时任务、运维脚本都能调，把她的状态改成「在修东西」之类。

## 改代码前须知

这个项目有几个历史遗留的坑，改之前请务必读 [`docs/部署与维护手册.md`](docs/部署与维护手册.md) 的第 2 章（结构与调用约束）、第 9 章（自检与事故清单）、第 10 章（改造风险）。

其中最容易踩的三条：

1. **`server.js` 顶层直接 `listen`，不要 `require` 它** —— 会在同进程里再启一个服务器、端口冲突。需要复用的只有 `engine.js`（纯逻辑库）。
2. **`server.js` 里有 8 个 `[EXTERNAL-DEP · PATCH n/8]` 标记块** —— 整文件重写会导致补丁丢失。改完用 `grep -c "PATCH .*/8" server.js` 检查是否还是 8。
3. **前端内联脚本要单独检查** —— `node --check` 不管 HTML 里的 `<script>`，改动后请真点一遍页面。

## 安全与隐私

**先说风险，别等出事**：这个项目的房间号只是「知道就能进」，**不是身份认证**。放在公网上任何人都能进来聊天、上传文件、调用 AI 接口（花你的额度）。它最初是局域网自用设计的，不是为公网准备的。

- **破坏性接口已加保护**：清理上传文件这类接口默认只允许**本机回环地址**调用。需要远程调用时，在 `.env` 里设 `AUTH_TOKEN`，请求带上 `x-auth-token` 头或 `?token=`。
- **`/api/chat` 是公开的模型代理**：谁能访问页面谁就能让它说话、消耗你的额度。**公网部署前务必加一层访问控制**（反向代理 + Basic Auth 最省事）。
- **`/api/health` 不再回显模型地址**，只告诉你「有没有配密钥」。
- **站点数据都在你自己的机器上**：聊天记录、上传文件、记忆都写在本地目录，站点本身不上传任何第三方。
  **例外**：① 聊天内容会发给你配置的模型服务（那是你自己的选择）；② 语音合成默认关闭，开启后文本会发往微软在线服务。
- **`.env`、`data/`、`workspace/` 已被 `.gitignore` 排除**，不会被误提交。
- AI 密钥只从环境变量读取，不写在代码里。

**想放公网？至少做这三件事**：反向代理加账号密码、`AUTH_TOKEN` 设一个随机串、限制 `/api/chat` 的调用频率（这一项本项目没做，需要你在代理层加）。

**怎么把 HTTP 换成 HTTPS**（Cloudflare Tunnel / 域名 + Caddy / 组网 / 自签四种做法的代价对比，含端口冲突与安全清单），见 **[docs/HTTPS与访问方式.md](docs/HTTPS与访问方式.md)**。

## 常见问题

**Q：没配 AI 密钥能用吗？**
能。站点、牌局、棋局、心有灵犀都正常，只是没有 AI 陪聊与出招。

**Q：端口被占用怎么办？**
`PORT=3001 bash deploy.sh`，或改 `.env` 里的 `PORT`。

**Q：手机能访问吗？**
能，把地址里的 `127.0.0.1` 换成本机内网 IP。要公网访问需要自己做端口映射或反向代理。

**Q：数据在哪？怎么备份？**
`data/` 与 `workspace/` 两个目录，直接复制走就是完整备份。恢复时放回原位即可。

**Q：语音念不出来？**
需要 Python 与 `edge-tts`：`pip3 install edge-tts`；不需要就把 `TTS_ENABLE=0`。

**Q：AI 记不住我说的话？**
先确认 `.env` 里 AI 配置正确，再看 `workspace/MEMORY.md` 是否有内容。长期记忆是异步沉淀的，不会立刻写入。
